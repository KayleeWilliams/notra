For years every site we shipped came with a cookie banner. Not because we wanted one, but because the analytics script needed one. This summer we moved all 14 client sites to Plausible, and 11 of them no longer show a banner at all.

## The questions clients actually ask

We went through a year of client calls and wrote down every question that needed analytics to answer. There were only four:

1. How many people visited this month?
2. Where did they come from?
3. Which pages do they read?
4. Did the launch post do better than the last one?

Plausible answers all four without cookies and without storing personal data. Everything else we used to track, like scroll depth heatmaps and session replays, nobody had opened in months.

## What we dropped

- **Per-user journeys.** We never acted on them.
- **Demographics.** They were estimates anyway.
- **Session replays.** Useful once during a redesign, then forgotten. We now run a moderated test with five people instead.

<Note>
  Plausible counts unique visitors with a daily rotating hash, so a returning visitor tomorrow counts as new. For a studio journal that is fine. For a checkout funnel it might not be.
</Note>

## How this journal does it

This site runs on Notra, and the Plausible setup is three lines in `blog.json`:

```json blog.json
"integrations": {
  "plausible": { "domain": "northwind-plausible.notra.site" }
}
```

Notra adds the script and allows it in the Content-Security-Policy. It only runs on the live site, so our own preview clicks never show up in the numbers.
