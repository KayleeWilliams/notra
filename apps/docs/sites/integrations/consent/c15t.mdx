Notra can add a [c15t](https://c15t.com) cookie banner and privacy settings dialog to your site. Visitors save their choice to a c15t backend that you control, either an [Inth](https://inth.com) project or a c15t backend you host yourself. Notra does not run that backend for you, because the consent records belong to you.

With the banner on, the [analytics providers](/sites/integrations/analytics/overview) in `integrations` wait until a visitor allows the **measurement** category. You can turn that off if you want analytics to load for everyone.

## Set up the backend

You need a c15t backend URL before you change your site. Pick one:

<Tabs>
  <Tab title="Inth">
    1. [Create an Inth project](https://inth.com). Sign-up is free.
    2. Add policy rules that cover the `measurement` category, so visitors can allow your analytics.
    3. Add your site's live origin, like `https://acme.com`, to the project's trusted origins. Add every custom domain your site uses.
    4. Copy the project's backend URL, like `https://acme.inth.app`.
  </Tab>
  <Tab title="Self-hosted">
    1. Run [`@c15t/backend`](https://c15t.com/docs/self-host/quickstart) on your own server with PostgreSQL, MySQL or SQLite. You own its migrations, backups and uptime.
    2. Serve it over HTTPS and allow your site's live origin in its CORS settings.
    3. Copy the backend's base URL, including any path prefix, like `https://consent.acme.com/api/c15t`.
  </Tab>
</Tabs>

The backend URL is public configuration, not a secret. It ends up in every page, so never put an API key or other credential in it.

## Turn on the banner

Add `c15t` to `integrations` in `blog.json`:

```json blog.json
{
  "$schema": "https://usenotra.com/schemas/blog.json",
  "name": "Acme",
  "integrations": {
    "posthog": {
      "apiKey": "phc_abcdefghijklmnopqrstuvwxyz0123"
    },
    "c15t": {
      "backendURL": "https://acme.inth.app",
      "prompt": { "variant": "bar", "position": "bottom" },
      "legalLinks": {
        "privacyPolicy": { "href": "https://acme.com/privacy" }
      }
    }
  }
}
```

After you publish the change and the production deployment finishes, open your live site in a private window. The banner appears once the browser has loaded your policy from the backend, and the footer gets a **Privacy settings** link that reopens the dialog.

## Analytics and consent

By default `gateAnalytics` is `true`. Google Analytics, Plausible, PostHog and Umami then load only after a visitor allows the measurement category, and they stay off for visitors who reject it. When a visitor withdraws consent later, the page reloads so that no analytics code keeps running.

If you don't need consent for analytics, for example because you only use a cookieless provider and your legal advice says that's fine, set `gateAnalytics` to `false`. Analytics then loads on every page view as it does without c15t, and the banner only covers what your c15t policy lists.

```json blog.json
{
  "integrations": {
    "plausible": { "domain": "acme.com" },
    "c15t": {
      "backendURL": "https://acme.inth.app",
      "gateAnalytics": false
    }
  }
}
```

<Note>
  Scripts in your repository's `scripts/` folder are not gated by c15t. They load on every page, so don't put tracking code there when you need consent for it. See [Custom scripts](/sites/custom-scripts).
</Note>

## Previews and local development

Preview deployments and `notra-sites dev` show the banner and dialog with your settings, so you can check how they look. They keep the choice in the browser only and never contact your backend or load analytics.

During `notra-sites dev`, the [c15t DevTools](https://c15t.com/docs/frameworks/react/components/dev-tools) panel also opens from a button in the corner of the page. Use it to inspect the stored choice, try other locations and languages, and clear your consent to see the banner again. It never ships to previews or your live site. To hide it locally, set `devTools` to `false`:

```json blog.json
{
  "integrations": {
    "c15t": {
      "backendURL": "https://acme.inth.app",
      "devTools": false
    }
  }
}
```

## Custom footers

The theme's footer shows the **Privacy settings** link on its own. If you replaced it with `footer.mdx`, add the `<PrivacySettings />` built-in where the link should go. It renders nothing when c15t is off.

```mdx footer.mdx
<footer className="border-t border-border py-8 text-sm text-muted-foreground">
  <div className="site-container flex gap-4">
    <span>© 2026 Acme</span>
    <PrivacySettings className="hover:text-foreground" />
  </div>
</footer>
```

Pass your own label as children, like `<PrivacySettings>Cookie settings</PrivacySettings>`.

## Appearance

By default the banner is a floating card in the bottom-left corner. It uses your site's fonts, surface, border and text colors and `colors.primary` for its buttons, and it follows your site's light and dark mode. Use these options to change its layout:

| Setting | Values | Description |
| --- | --- | --- |
| `prompt.variant` | `floating`, `bar`, `widget`, `wall` | Shape of the banner. `floating` is a card, `bar` spans the edge of the screen, `widget` is a compact corner card and `wall` blocks the page until the visitor chooses. Defaults to `floating` |
| `prompt.position` | Depends on `variant` | `floating` takes `bottom-left`, `bottom-right`, `top-left`, `top-right`, `bottom-center` or `top-center`. `bar` takes `top` or `bottom`. `widget` takes the four corners. `wall` has no position |
| `prompt.blocking` | boolean | Dim the page and trap focus while the banner is open. Not available for `wall`, which always blocks |
| `prompt.direction` | `row`, `column` | Lay the buttons out in a row or a column. Defaults to `row` |
| `prompt.uiProfile` | `compact`, `balanced`, `strict` | `compact` sizes buttons to their labels, while `balanced` and `strict` stretch them to full width. Defaults to `compact` |
| `preferences.blocking` | boolean | Dim the page while the privacy settings dialog is open. Defaults to `true` |
| `preferences.direction` | `row`, `column` | Button layout in the dialog |
| `preferences.uiProfile` | `compact`, `balanced`, `strict` | Button sizing in the dialog |
| `disableAnimation` | boolean | Show the banner and dialog without animations. Visitors who prefer reduced motion never see them animate |

Your c15t policy decides which buttons a visitor must see. If a layout hides a button the policy requires, c15t shows it anyway.

### Colors and corners

To give the banner its own look, set `theme`. Each color is a hex value, and any color you leave out keeps following your site:

```json blog.json
{
  "integrations": {
    "c15t": {
      "backendURL": "https://acme.inth.app",
      "theme": {
        "colors": { "surface": "#FFFBF5", "primary": "#E4572E" },
        "dark": { "surface": "#1C1917", "primary": "#F08A5D" },
        "radius": "large"
      },
      "hideBranding": true
    }
  }
}
```

| Setting | Values | Description |
| --- | --- | --- |
| `theme.colors` | Hex colors | Light mode colors. Keys are `primary`, `primaryHover`, `textOnPrimary`, `surface`, `surfaceHover`, `border`, `borderHover`, `text`, `textMuted`, `overlay`, `switchTrack`, `switchTrackActive` and `switchThumb` |
| `theme.dark` | Hex colors | Dark mode colors, with the same keys |
| `theme.radius` | `none`, `small`, `medium`, `large` | Corner rounding of the banner, dialog and buttons. Defaults to `medium` |
| `hideBranding` | boolean | Hide the "Secured by c15t" badge on the banner. Check that your Inth plan allows it |

## All options

| Setting | Type | Default | Description |
| --- | --- | --- | --- |
| `backendURL` | `https://` URL | Required | Your Inth project URL or self-hosted c15t backend, including any path prefix |
| `gateAnalytics` | boolean | `true` | Load the analytics in `integrations` only after the visitor allows the measurement category |
| `prompt` | object | Floating card | Banner layout, see [Appearance](#appearance) |
| `preferences` | object | | Dialog layout, see [Appearance](#appearance) |
| `legalLinks.privacyPolicy` | `{ href, label? }` | | Link shown in the banner and dialog. `href` is an `https://` URL or a path, and `label` replaces the translated link text |
| `legalLinks.cookiePolicy` | `{ href, label? }` | | Same as above |
| `legalLinks.termsOfService` | `{ href, label? }` | | Same as above |
| `locale` | Language code | Visitor's browser language | Force one language: `bg`, `cs`, `cy`, `da`, `de`, `el`, `en`, `es`, `et`, `fi`, `fr`, `ga`, `gu`, `he`, `hi`, `hr`, `hu`, `id`, `is`, `it`, `lb`, `lt`, `lv`, `mt`, `nb`, `nl`, `nn`, `pl`, `pt`, `rm`, `ro`, `sk`, `sl`, `sv` or `zh` |
| `crossSubdomain` | boolean | `false` | Share the consent cookie with every subdomain, so a choice on `blog.acme.com` also applies on `acme.com` |
| `expiryDays` | 1 to 730 | `365` | Days until the stored choice expires and the banner shows again |
| `disableAnimation` | boolean | `false` | Show the banner and dialog without animations |
| `theme` | object | Your site's theme | Colors and corner rounding, see [Colors and corners](#colors-and-corners) |
| `hideBranding` | boolean | `false` | Hide the "Secured by c15t" badge on the banner |
| `devTools` | boolean | `true` | Show the c15t DevTools panel during `notra-sites dev`. Never included in previews or the live site |

The [`blog.json` schema](https://usenotra.com/schemas/blog.json) checks every option, so your editor autocompletes the values above and flags a position that doesn't fit the variant.

## Content-Security-Policy

Notra adds your backend's origin to `connect-src` and allows the analytics scripts that c15t loads, so you don't need to touch `security.allowedOrigins`. See [Content-Security-Policy](/sites/custom-scripts#content-security-policy).

## Troubleshooting

If the banner never appears, check that your site's origin is in the Inth project's trusted origins or in your backend's CORS settings. The browser console shows the blocked `/init` request.

If analytics never loads, make sure your policy has a `measurement` category and that you allowed it. Open **Privacy settings**, turn on the analytics switch and save.

If the link is missing from a custom footer, add `<PrivacySettings />` to `footer.mdx`. The link stays hidden until the policy has loaded, and it stays hidden for visitors whose region needs no consent UI.
